Capabilities are optional tools that Mate can configure during `mate companion setup` and sync into linked working repositories when you run `mate opencode` or `mate claude`.

Capabilities are selected per companion. They affect the dependency plan used by
`mate install`; selecting a capability never silently enables another optional
capability.

## Projects

- [OpenSpec](https://openspec.dev/) for spec-driven change workflows
- [Graphify](https://github.com/safishamsi/graphify) for repository knowledge graphs
- [TokenSave](https://github.com/aovestdipaperino/tokensave) for code-graph exploration through MCP
- [React Doctor](https://www.react.doctor/) for React diagnostics

Mate can also wire in these optional projects:

- [RTK](https://github.com/rtk-ai/rtk) for compact command output (Apache-2.0)
- [Context7](https://github.com/upstash/context7) for library documentation through MCP (MIT)
- [Context Mode](https://github.com/mksglu/context-mode) for session context management (Elastic License 2.0)

Mate installs each project from its own source; it does not bundle them.

## How They Fit

The default workflow starts with `mate install` in the working repository, then
`mate companion link`. Linking reads the selected companion capabilities and
installs their resulting dependency plan automatically.

Use `mate companion setup` in the companion repository when you need to change
those selections. Run `mate install` afterward to refresh the dependency plan.
Then `mate opencode` and `mate claude` launch from the working repository with
the selected companion-managed capabilities available.

## Skill Locations

Capability skills live in two companion skill roots:

- `.claude/skills/` for Claude.
- `.agents/skills/` for every other agent runtime, currently OpenCode.

A wrapped working repository gets a link to each companion skill folder and
command folder under its own `.claude/`, because Claude does not load commands
from the companion directly.
Mate only manages the skills it installs, so your own skills and third-party
skills in `.agents/skills/` stay untouched. Companions created by earlier Mate
versions kept OpenCode skills in `.opencode/skills/`. Run
`mate companion update` once to move them, then commit the result.

## Capability Details

### OpenSpec

OpenSpec commands are routed through the companion context:

```sh
mate cap openspec <subcommand> [args...]
```

Mate ships two schema profiles and installs both into the companion. Schema choice
selects the artifact set; both profiles still explore before proposing:

- `mate-v1`: the complete `proposal → specs → design → tasks` artifact set
- `mate-minimal`: the short `specs → tasks` artifact set, with parser-compatible
  requirements written as user stories and Given/When/Then acceptance criteria

Choose `mate-minimal` only when every gate is true:

- one repository and one Area
- no new dependency or data migration
- no public API change or breaking behavior
- no cross-cutting architecture or unresolved technical decision

If any gate is false or unclear, use `mate-v1`. Its proposal, specs, design, and tasks
artifacts are required, but they can stay concise for simple changes. `mate-v1` is
always the companion default: setup writes `schema: mate-v1` into
`openspec/config.yaml`, replacing the default `openspec init` writes, and leaves the
file's other keys alone. `mate-minimal` is never the companion default.

Either profile can be named for one change:

```sh
mate cap openspec new change <name> --schema mate-v1
mate cap openspec new change <name> --schema mate-minimal
```

OpenSpec records the selected profile in the change's `.openspec.yaml`.

#### OpenSpec Version And Generated Files

Mate ships the OpenSpec CLI (`@fission-ai/openspec`) at one exact version per
Mate release. Every OpenSpec process Mate starts runs that copy: setup,
`mate companion update`, `mate cap openspec`, `mate artifact archive`, and the
`openspec` wrapper agents call. Mate does not install, upgrade, or use a
globally installed `openspec`; a global install of another version stays as it
is for your other projects. A new OpenSpec version arrives with a new Mate
release. `mate doctor` shows the bundled path and version.

{/* breaking:start */}

Mate generates no OpenSpec skills or `/opsx` commands. Setup and
`mate companion update` run `openspec init --tools none`, which writes only the
`openspec/` folder. The workflow text OpenSpec would put in its skills ships
inside the Mate skills instead, as a `references/` file taken from the bundled
version: `mate-explore-change`, `mate-propose-change`, and `mate-apply-change`
each follow theirs, and `mate-propose-change` also follows the update workflow
in its revise mode. Revise mode revises a change's planning artifacts, for
example after a review, and keeps them consistent; it edits no code. Every Mate
user on the same release follows the same text.

Companions set up by earlier Mate versions still hold the generated
`openspec-*` skills and `/opsx` commands. The next `mate companion update`
removes them, and the link refresh drops their links from wrapped working
repositories. Commit the result. Launches never touch them.

{/* breaking:end */}

Every OpenSpec process Mate starts runs with `OPENSPEC_TELEMETRY=0` and
`OPENSPEC_NO_UPDATE_CHECK=1`.

### Delta And Canonical Specs

A change writes proposed requirements as delta specs under
`openspec/changes/<name>/specs/<capability>/spec.md`. The durable current
contract lives under `openspec/specs/<capability>/spec.md` as the canonical spec.
Do not edit canonical specs while planning a change.

`openspec archive` is the bridge: it merges the delta requirement blocks into the
canonical spec and moves the change into `openspec/changes/archive/<date>-<name>/`.
Use `mate-archive-change` (`mate artifact archive`) to archive: it also records
the change's delivery branch in `delivery.yaml`, and it may run before that
branch is merged. `mate-publish-artifact`, built on `mate artifact publish`, is
the sanctioned terminal flow for the archive and its follow-up Git work; it
holds an archive back until its delivery branch is merged. The whole sequence,
from clarifying intent to publication, is walked through in
[Your First Change](/docs/scenarios/first-change).

### Graphify

Graphify manages a repository knowledge graph and companion-managed agent
wrappers. Refresh its index directly or through the combined index command:

```sh
mate cap graphify <subcommand> [args...]
mate cap index --graphify
```

### TokenSave

TokenSave provides code-graph exploration through MCP and keeps its native
`.tokensave` store in the working repository. Refresh it with:

```sh
mate cap index --tokensave
```

### React Doctor

React Doctor installs the `mate-react-doctor` skill for Claude and OpenCode. It
adds no hooks and never scans in the background: it runs only when the skill is
invoked.

With OpenSpec, the shared Mate conventions add a
`[skill:mate-react-doctor]` verification task to the end of every Area whose
tasks change React code. The apply phase works through that task, and before it
reports a change complete, it runs the skill for any React Area that has no
checked verification task. The skill scans the change's diff with Mate's pinned
React Doctor binary, fixes regressions the change introduced, and reports what
it could not fix. Outside an OpenSpec change, invoke the skill directly.

A task's `[skill:<name>]` tag names only a skill installed in the Companion
Repository, under its `.claude/skills/` or `.agents/skills/`. User-global,
plugin, and built-in skills are never tagged, so every session that shares the
companion runs a tagged task the same way. When no companion skill applies, the
task stays untagged.

React Doctor is configured during setup and does not have a separate `mate cap`
command.

### Companion Mentions

Companion Mentions (`companion-mentions`) is an optional capability that ships
with Mate. It lets a Claude session in a Working Repository mention Companion
Repository files and folders, whether `mate claude` started it or plain `claude`
runs in a wrapped repository. It is not selected by default: select it in
`mate companion setup`, then run `mate wrap` or start a session with
`mate claude`.

Type `@` followed by a filename or path, such as `@tasks` or `@acme/tasks`, to
search the companion as well as Claude's own files. `@mate:` uses the same search;
a path ending in `/` browses its direct children. A bare `@` offers a companion
gateway and top-level folders. Search returns up to 15 companion matches, and
selecting one inserts an `@mate:<path>` mention. A sent mention attaches that file,
or a list of a folder's entries. A file mention can carry a line range, such as
`@mate:openspec/config.yaml#L1-5`.
Claude puts its own results above plugin rows; if many match, use the arrow keys
or type `@mate:` to reach companion results.

- It loads in sessions started with `mate claude` and in plain `claude` sessions
  of a repository wrapped for Claude, where Claude Code must trust the folder.
  `mate doctor` shows under Plain Sessions whether plain sessions load it. A
  plain session in a repository that is not wrapped does not.
- It uses the companion that `mate claude` hands it. In a plain session it asks
  Mate through [`mate session context`](/docs/reference/commands#session-context),
  which reports only a companion you registered that links the repository.
- It needs Claude Code 2.1.292 or later. Older versions start normally and
  ignore it.
- In a session inside the companion, such as `mate claude -- --companion`, it
  adds no menu rows, because Claude's own rows already list those files. A
  typed `@mate:` mention still attaches.
- It does not offer, list or attach secret files, whether named directly or
  through a link. It applies the companion's
  [secret policy](/docs/concepts/secret-guardrails). In a plain session a
  `secrets` change applies from the next mention, and the menu follows within
  30 seconds. A `mate claude` session keeps the policy from its launch, so the
  change reaches it at the next `mate claude`.
- If you installed the `mate-companion-mentions` mod into Claude yourself,
  disable that copy. Mate's copy is a different plugin ID, so it does not
  replace yours, and with two enabled plugins of one name Claude leaves out the
  hooks of one of them.
- It runs on macOS and Linux. Its Windows path handling is covered by unit
  tests but has not been tried by hand.

`mate doctor` lists `companion-mentions` among the Capabilities that contribute
a Claude plugin. To turn it off, deselect it in `mate companion setup`. If the
rows do not appear, see
[`@mate:` Rows Are Missing](/docs/troubleshooting#mate-rows-are-missing).

## Index Synchronization

Launches automatically refresh enabled code-exploration capabilities. You can
also refresh them explicitly from a linked working repository:

```sh
mate cap index
```

If both Graphify and TokenSave are enabled, Mate refreshes TokenSave and then
Graphify so Graphify sees the resulting repository state.
