---
title: Secret Guardrails
description: How Mate keeps secrets out of agent context, indexes, and companion artifacts.
---

Mate keeps secret files and secret values away from the agents it runs. The
guardrails are on by default and layered, so no single missed rule lets a
secret through. One switch in the companion config turns them all off.

## Secret Files

A path is a secret file when it matches a deny pattern and no allow pattern.
An allow match always wins. Patterns use gitignore syntax:

- `*` and `?` match within one folder or file name, `**` across folders,
  `[0-9]` or `[!a-c]` one character of a set (never `/`), and `\` makes the
  next character plain (`\#notes`);
- a pattern without a slash matches the file name at any depth; one with a
  slash matches the end of the path (`config/master.key` also covers
  `app/config/master.key`);
- a pattern ending in `/` names a folder: the folder and everything in it
  match, so `private/` covers `private/token.txt`. A pattern without that slash
  matches files only, not what a folder of that name holds;
- a leading `!` is a plain character, not a negation; list files to keep
  readable under `allow`.

Matching ignores letter case on every platform, so `.ENV`, `ID_RSA`, and
`Prod.KEY` are secret files too. A `\` in a path separates folders only on
Windows; elsewhere it is part of the file name, so `public\server.key` is one
file and an allow pattern for `public/**` does not cover it. Pattern text that
Mate writes into another tool's configuration, such as the projected deny rules
or `.graphifyignore`, stays as written and follows that tool's own rules.

| Default deny patterns              | Default allow patterns |
| ---------------------------------- | ---------------------- |
| `.env`, `.env.*`                   | `.env.example`         |
| `*.pem`, `*.key`, `*.p12`, `*.pfx` | `.env.sample`          |
| `id_rsa`, `id_ecdsa`, `id_ed25519` | `.env.template`        |
| `.netrc`, `.pgpass`, `.npmrc`      | `.env.dist`            |

`.npmrc` is on the list because it often holds a registry `_authToken`. npm
itself still reads it; only agents are kept out.

## The Layers

| Layer                  | What it does                                                                                                                                                                                                                                                                                                                                             | Picks up a config change            |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| Guidance               | Injects a `secret-handling` rule: never read, print, copy, or write secrets; read only the example files; refer to a secret by its variable name.                                                                                                                                                                                                        | Next session                        |
| Hook and middleware    | Blocks Read, Write, Edit, MultiEdit, NotebookEdit, and patch calls on a secret file, content searches (Grep) in a secret file or with a glob aimed at one, and shell commands that name one, in Claude Code and OpenCode.                                                                                                                                | Next tool call                      |
| Companion content scan | Scans what an agent writes into the Companion Repository with secretlint's recommended preset and blocks the write on a finding or a scanner error.                                                                                                                                                                                                      | Next tool call                      |
| Projected deny rules   | Adds `Read`/`Edit` deny rules for the default secret files to Mate's managed Claude `permissions.deny` list (Claude's `Edit` rule also covers `Write`) and `read`/`edit` rules to OpenCode's permissions.                                                                                                                                                | Next launch or `mate wrap`          |
| `@mate:` mentions      | With the optional [Companion Mentions](/docs/capabilities#companion-mentions) plugin, keeps secret files out of Claude's `@mate:` rows and answers a mention of one with a note. In a plain `claude` session it asks Mate for the rules at each mention, and its rows follow within 30 seconds. A `mate claude` session keeps the rules from its launch. | Next mention, or next `mate claude` |
| Indexer exclusion      | Excludes secret files from TokenSave's `.tokensave/config.json` and from a Mate-managed region of `.graphifyignore`.                                                                                                                                                                                                                                     | Next setup or `mate cap index`      |
| Graphify gate          | Before every extraction, including ones an agent runs through the `graphify` wrapper, rewrites the `.graphifyignore` region and passes the secret patterns as `--exclude`. Afterwards it removes any secret that still reached the output and keeps the rest. It never stops graphify.                                                                   | Every extraction                    |
| Publish scan           | `mate artifact publish` scans the files it would commit and stops at a `secret-scan` step on a finding.                                                                                                                                                                                                                                                  | Every publish                       |

Refusals name the path and, for content findings, the line and rule id. They
never print the secret itself.

A content search counts as aimed at secret files when its glob names one
(`server.key`, `**/.env.local`, `certs/*.key`, each `{a,b}` alternative on its
own) or matches one by pattern (`.env*`, `*.key`); `**/*`, `*.ts` and a `!`
exclusion do not.

When the hook or middleware fails on a call, or cannot read a shell command
(one nested more than 64 substitutions deep), it refuses the call rather than
let it run unchecked; see
[Artifact Write Blocked By The Guardrail](/docs/troubleshooting#artifact-write-blocked-by-the-guardrail).

The hook and middleware judge a read, search or write path by its name and,
when something exists at that path, by where it leads. With `public.txt` linked
to `cert.key`, reading `public.txt` is refused, and the refusal names the link
as `target:` and the secret file as `lands in:`. The path is looked up as
written, so `forward/../innocent.txt` is checked where the system reads it even
when `forward` is a link elsewhere; `target:` shows the path normalised. Shell
commands are judged by the names they spell, with quotes and backslashes read
as Bash reads them (`"pub\lic/server.key"` names `pub\lic/server.key`); a link
named in a command is not followed. An ANSI-C string `$'…'` is read as Bash
reads it: `\'` inside does not end it, and escapes are decoded, so
`$'.e\x6ev'` names `.env`. A decoded NUL (`\0`, `\x00`, `\c@`…) ends the
string, as it ends the argument Bash passes, so `$'.env\0ignored'` names
`.env`.

The shell check errs toward refusing: a refused command that was harmless can
be rephrased, a secret file read unseen cannot be undone. It reads each line of
a command on its own and the whole command once more, and counts the file
names of both readings, so a quote it misjudges on one line does not hide the
names on the next. The command inside a substitution is read too, quoted or not:
`printf "%s" "$(cat cert.key)"` is refused like `cat cert.key`. A comment is
read like any other text: `git status # leave server.key alone` is refused
because the comment names `server.key`. Rephrase the comment or drop it.

The one text the shell check skips is a heredoc body, and only when its marker
reads as one both on its own line and in the whole command, with the delimiter
taken as Bash takes it: the whole word after quote removal, so `<<E"OF"` ends at
`EOF` and `<<EOF+` at `EOF+`. A marker inside a quote, in arithmetic
(`$((1<<2))`), or with a delimiter holding `$` or a backtick skips nothing. The
check is a heuristic, not a parser: a marker it takes for real after misreading
an earlier quote still hides the lines it takes for the body.

The content scan judges what the companion file will hold. When an OpenCode
patch moves a file into the Companion Repository, the scan reads the moved
file's whole current content together with the lines that every section of
the patch touching either end of the move adds, so a secret kept as an
unchanged line, or added by an earlier section, is caught. In a moved file,
`secretlint-disable` and `secretlint-enable` comments do not apply: the patch
can remove them, so they could hide a secret the file will hold. A move into
the companion is refused when the moved file is not a regular file, cannot be
read, or is larger than 1 MiB, since the scan could not see all of it:

```text
Mate guardrail: a file moved into the Companion Repository could not be checked for secrets, so the move is blocked.
```

A write counts as a companion write by where it lands; on a filesystem that
ignores letter case (the macOS default), `ACME-COMPANION/notes.txt` is in the
companion `acme-companion` and is scanned.

The same hook and middleware also keep agent artifacts out of the working
repository, with the same verdict in Claude Code and OpenCode. See
[Artifact Write Blocked By The Guardrail](/docs/troubleshooting#artifact-write-blocked-by-the-guardrail)
for what they refuse and allow.

Only agent tool calls and Mate's own commands are guarded. Your shell, your
editor, and your Git are not. A shell command that reaches a secret without
naming it, such as `env` or an unscoped `grep -r`, is covered by the guidance
rule only.

## Configuration

Add a `secrets` block to the companion's `.mate/config/framework.yaml`. Every
field is optional.

```yaml
secrets:
  guardrails: true # false turns every layer off
  deny: ["config/master.key.enc"] # added to the defaults
  allow: [".env.test"] # added to the defaults; an allow match wins
```

- Extra `deny` and `allow` patterns add to the defaults; they never replace
  them.
- Extra `deny` patterns are enforced by the hook, the middleware, the
  indexers, and `@mate:` mentions. They are not projected into Claude or
  OpenCode deny rules.
- A missing or unparseable `framework.yaml` keeps the guardrails on with the
  defaults. A broken config never disables protection.
- The config is read where the companion path leads, links followed before
  `..` as the system does: with the companion set to `forward/../companion`
  and `forward` a link to `outside/sub`, the policy comes from
  `outside/companion`, not from a `companion` folder next to `forward`. The
  guard, a launch's environment (`MATE_ARTIFACT_PATH`), a projection,
  `mate session context` and `mate setup` resolve a companion path this way.
  A companion path stored in Mate's registries (the Working Repository's own
  list and your Mate configuration) is not resolved this way yet, and when
  the folder a path leads to is missing, a launch uses the normalised folder
  instead. Avoid writing a companion path with `..` through a link.

For a documented fake key in an artifact, wrap it in secretlint's inline
comments instead of turning the guardrails off:

```md
<!-- secretlint-disable -->

AKIA... (example only)
<!-- secretlint-enable -->
```

This works for a file an agent writes or edits in the companion, not for one an
OpenCode patch moves there: a move ignores the comments, so moving a file with
a disabled fake key into the companion is refused. Write the file in the
companion instead.
