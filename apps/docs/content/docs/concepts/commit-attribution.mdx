---
title: Commit Attribution
description: How Mate keeps AI co-author trailers out of the commits agents create.
---

Agents must not credit an AI model as co-author of a commit. Mate enforces this
in two places, so the trailer is never written and no history has to be rewritten
to remove it.

## Claude Code's Attribution Is Turned Off

Claude Code tells every session to end commit messages with a
`Co-Authored-By: Claude` trailer unless its `attribution` setting hides it. Mate's
managed Claude settings, and the settings a Claude wrap places, hide it. A
setting of your own wins over Mate's; see
[Commands](/docs/reference/commands#claude-wrap-then-launch).

## The Commit Is Refused

A guard in the Claude Code hook and the OpenCode middleware refuses a shell
`git commit` whose message carries a `Co-Authored-By:` trailer naming a model:
one that mentions Claude, Anthropic, GPT, OpenAI, Codex, Gemini, Copilot, or
opencode anywhere, in any letter case, so `ChatGPT` counts too. The commit is refused before it exists:

```text
Mate guardrail: Co-Authored-By trailers that credit an AI model are not allowed in this repository.
No commit was created. Rerun the same commit without the Co-Authored-By trailer; do not amend or rewrite history to remove it.
```

The guard runs whatever the attribution setting says, so it also covers a user
whose own setting adds a model trailer. Human co-author trailers pass.

The guard finds `git commit` where the other guardrails find a command: behind
wrappers and their option values (`sudo -u bob`, `nice -n 5`, `env -S "…"`,
`xargs`), after `if …; then`, and inside a substitution, quoted or not. A
substitution where the command's name goes may expand to nothing, a path or a
wrapper, so after one (`$(…) git commit`, `$(…)git commit`) any later `git`
counts as the name. A `git commit` inside a quoted argument
(`echo "a && git commit …"`) is text.

It reads only message text in the command itself: `-m` and `--message` values
(`-m x`, `-mx`, `-am x`, `--message=x`) as Bash passes them, `$'…'` decoded;
`--trailer` values; a here-string (`<<< "…"`); the text a substitution in any
of the commit's arguments or redirects carries, even when that text never
reaches the message (`-F <(cat <<'EOF' … EOF)`, `< <(…)`); and the heredoc
bodies the commit reads, its own or piped in, such as
`-m "$(cat <<'EOF' … EOF)"`, `git commit -F - <<'EOF'` or
`cat <<'EOF' | git commit -F -`. A body piped into `{ … }`, `( … )`, `if`, a
loop or `case`, also behind `time`, or given on its closer (`done <<'EOF'`),
reaches every command in it, and every body read inside such a group reaches a
pipe after it; `|&` pipes like `|`. A shell function's body is read where it
is defined; a body is not followed into or out of a call
(`f | git commit -F -`). It reads no files, so
`git commit -F <file>`, `git commit -t <template>`, and messages written in an
editor are not checked, also when the same command wrote the file from a
heredoc (`cat <<'EOF' > msg.txt; git commit -F msg.txt`). Reading shell commands is
best effort: `bash -c`, `eval` and scripts are not read into.
Only agent tool calls are guarded; your own shell and Git are not.
