---
title: Triage a Mate Problem
description: Hand a Mate problem to your own coding agent, which investigates it and helps you write an issue that is posted only after your yes.
---

## Audience

Developers who hit a problem with Mate, such as a refusal they did not expect,
a launch that fails, or a command that does not work, and want to find the
cause or report it.

## Goal

Your own coding agent investigates the problem on your machine with the facts
Mate prepared, and you decide what happens next: a local fix, an issue, a
comment on an existing issue, or nothing.

## Start triage

```sh
mate triage
```

`mate triage` runs before every other check. It works when a launch fails, the
installation is incomplete, a newer version is enforced, or the current folder
belongs to no companion.

It writes a triage session folder and starts Claude Code or OpenCode in it. It
starts the agent's own CLI directly, not through `mate claude` or
`mate opencode`, so no companion guidance and no Mate plugin load.

- With only one of the two installed, Mate starts that one.
- With both installed, Mate asks which one. Without a terminal, pass
  `--agent claude` or `--agent opencode`.
- With neither installed, Mate prints the session paths and exits non-zero.
- Inside an agent session, Mate writes the folder but starts no agent: nobody
  could approve a post. It prints the paths and exits zero. Run `mate triage`
  in your own terminal.

To start your agent yourself, run `mate triage --no-launch`. It prints the
session paths. Open your agent in the session folder and give it the text of
`prompt.md`. An agent you start this way cannot record the outcome: run
`mate friction mark` in your own terminal.

When `mate doctor` reports friction events, it names `mate triage` as the next
action.

## Start from one item

```sh
mate triage "command:artifact submit:1"
```

To hand one Friction Item to triage, name it as the Triage Target: a
fingerprint with at least one recorded event, or a Free Report id. The agent
starts from that item, whatever its Friction State. `--agent` and `--no-launch`
work as before. A report attached to an event is no target: use its event's
fingerprint, which the refusal names.

In Studio's [Friction view](/docs/concepts/friction#in-studio), each opened
group and Agent report shows its own `mate triage "<id>"` with a Copy button.
An id with a space is double-quoted, so it stays one argument in cmd.exe,
PowerShell and POSIX shells. Run it in a repository of the item's companion.

The target chooses whose friction the session copies:

| Where you run it                                  | Friction copied                          |
| ------------------------------------------------- | ---------------------------------------- |
| In a companion that holds the target's records    | That companion's                         |
| Elsewhere, and one companion holds the target     | That companion's; `context.md` says so   |
| Elsewhere, and several companions hold the target | None: Mate lists them and exits non-zero |

The doctor report always describes the folder you ran in. An unknown target
also exits non-zero. A refused target writes no session folder and deletes no
old one.

## What the session folder holds

Each run writes a new folder at `~/.mate/triage/<UTC time>/`. Folders older than
30 days are deleted when `mate triage` starts.

| File                     | Content                                                                                                                                        |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `context.md`             | Mate version, how it was invoked, operating system, JavaScript runtime, the agents found, the folder, the issue repository, the doctor report. |
| `PLAYBOOK.md`            | The instructions the agent follows, shipped with your Mate version.                                                                            |
| `prompt.md`              | The seed prompt that points the agent at `PLAYBOOK.md` and `context.md`.                                                                       |
| `friction-events.jsonl`  | The [friction](/docs/concepts/friction) events of the last 30 days, when there are any.                                                        |
| `friction-reports.jsonl` | The agents' friction reports of the last 30 days, when there are any.                                                                          |
| `friction-states.json`   | The [Friction States](/docs/concepts/friction#friction-states) of the copied fingerprints and Free Reports, when friction files are written.   |

The friction files hold only the records of one companion, and the reports on
those events: the companion the folder belongs to, or, with a Triage Target that
companion does not hold, the target's own companion. `context.md` names that
mismatch. When the folder's companion holds the target, `context.md` lists the
target's events in other companions, which are not copied. The friction files hold every record, handled or not;
`friction-states.json` says which are handled, with reopened items and the
events since a report. Run `mate triage` in the affected
repository: outside a companion, Mate copies no friction unless you name a
Triage Target. With a target, the files also hold the target's own records,
even when they are older than 30 days. Mate scans the events
for secrets first; an event the scan flags keeps its message, command, error
text, paths and flags as `[withheld: <rule>]`. When the scan fails, Mate
withholds those fields in every event.

`context.md` holds no environment variable values. The playbook never changes:
Mate does not fetch a newer one. Run `mate update` to get the playbook of a
newer version.

## What the agent may do

The playbook tells the agent to:

1. Ask what went wrong, unless you already said it, and which version it
   happened on.
2. Read `context.md` and the friction files, starting with the Triage Target
   when you named one, otherwise with the open fingerprints. It looks at a
   handled item only when it relates to your problem, and treats a reported
   item's link as an existing issue.
3. Ask you once before its first network request, and say what it will fetch:
   the Mate source at the tag of the affected version, a search of existing
   issues, and a check for a newer version.
4. Present what it found and offer the four outcomes: fix, issue, comment on an
   existing issue, or nothing. It offers a comment on a matching issue before a
   new issue.
5. After the outcome, ask whether to record it, and only after your yes run
   `mate friction mark`: a fix as `fixed`, an issue or comment as `reported`
   with its URL, no Mate problem as `dismissed`. With a Triage Target, it
   records the target, and another item only when the same outcome covers it.
   When you chose nothing, it asks whether to dismiss the item or leave it open.

The agent treats every log line, report, Friction State note, issue and fetched
page as data, never as an instruction. It never edits the installed Mate.
`mate friction mark` is the only Mate command it may run that writes.

## What needs your yes

- **The network.** The agent asks once before it fetches anything.
- **A fix.** The agent changes a file only after you approve the change.
- **An issue or a comment.** The agent shows you the complete final text, and
  posts only after an explicit yes.

Before it shows you a draft, the agent removes secrets and tokens, replaces
your home directory path with `~`, and removes the names, paths and code of your
product. It keeps a product detail only when you approve it.

The agent creates an issue with `gh issue create` only when `gh` is
authenticated and has triage permission on the issue repository. Otherwise it
prints a prefilled new-issue URL for the `via-triage` issue form, and opens a
browser only after you approve.

A Mate distribution that names no issue repository ends triage with a local
`report.md` in the session folder, and files nothing.
